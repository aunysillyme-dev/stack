# Share a stack

Document a workflow you use. Include its purpose, inputs, tools, steps, output and a way for another person to check the result. Free, paid and mixed workflows are welcome. Describe access and costs as accurately as your experience allows.

1. Copy [the JSON template](templates/workflow.json) to `<category>/community/<your-github-login>/<workflow-name>.json`. Use your lowercase GitHub login and a short lowercase filename with hyphens. Use a review date no later than today in UTC, link tools to official public HTTPS sources by hostname, and describe what you actually tried.
2. In `credits`, give each contributing author's GitHub handle and a specific, factual description of their work. Include yourself and any applicable coauthors who agree to public credit. The fields are plain text, not Markdown. The entry itself is the readable workflow description and byline. Existing entries without `credits` remain valid; add accurate credits when updating one.
3. Run `python3 scripts/credits.py --write`, then `python3 scripts/validate.py` and `python3 -m unittest discover -s tests -v`. Commit the generated README change with your JSON. Open a PR, describe your sources and personally check the first line of the description after reading the [contributor certification](CONTRIBUTOR-CERTIFICATION.md). You can submit from GitHub without a Git sign-off.
4. A maintainer reviews the work, rights and credit before merge. Update your workflow through another PR when it changes. For a curated correction, open an issue with the location and source; a maintainer handles curated data and other repository changes in a maintainer-authored PR.

Find the available top-level category folders in [the catalog](catalog.json). A maintainer registers a new category before it accepts community entries. Outside contributors may change only JSON workflow files directly inside their own lowercase login folder in an existing category, plus the generated README credit block. The scope check uses the PR author, checks both paths of a rename, and rejects moves between folders. Additions and deletions across different folders cannot be combined in one outside PR. The README check reconstructs all bytes outside the block from the trusted base and checks the generated block exactly. It does not grant permission to edit another author's work. For each newly credited coauthor, include the PR-template confirmation line linking their own comment on this PR. Maintainers verify authorship and scope of the comment. A maintainer handles changes to another person’s prior credit after checking with that person. The author field must match the folder; automated checks cannot establish identity, ownership, accuracy or consent.

## Rights, sources and credit

Write original descriptions in your own words. Identify any third-party text, data, examples or components, their sources, applicable licenses and required attribution; link examples only when you have permission to share them. Do not assume that a public example can be republished. Explain material AI assistance and the provenance of its inputs and outputs so reviewers can assess the submission. Obtain employer permission from an authorized person where needed. Keep private, personal and client data, credentials and confidential material out of files, links, PRs and Git history. Use names and marks accurately and do not imply endorsement.

Your certification applies to the material you intentionally submit under the applicable [repository licenses](LICENSE.md). For original solo work, check the first line yourself and describe the source. A maintainer reviews the final change. Disclose joint authors and additional rights holders whose permission is needed. Link their account-authored confirmations or arrange verification of an authorized representative. Identify the license and provenance for third-party material. Get fresh confirmation when the rights, authorship or certification terms change. Issues and Discussions do not certify or authorize republication. Public credit requires consent.

Credit is specific and durable. Keep existing bylines and descriptions when improving or renaming an entry, updating the README links via the renderer. Retire a workflow by retaining its credited JSON at its existing path and clearly marking its purpose as retired, rather than deleting the record; preserve factual credit and regenerate the README. If a move is necessary, retain all bylines at the new path and review links and history. A contributor may request a correction through an issue or PR. Review requests to add or change credit with the people involved, including opt-in before naming someone for idea-only help or collaborator attribution. Do not infer permission from public discussion.

## Help and conduct

Use [issues](https://github.com/aunysillyme-dev/stack/issues) for errors, workflow or feature proposals, and credit corrections. Use [Discussions](https://github.com/aunysillyme-dev/stack/discussions) for questions and ideas. These public spaces and PRs follow the [organization Code of Conduct](https://github.com/aunysillyme-dev/.github/blob/main/CODE_OF_CONDUCT.md), including its moderation expectations. Do not post sensitive information in public. For a security vulnerability, use the repository’s Security tab and select “Report a vulnerability.” For sensitive rights or attribution evidence, ask a maintainer to arrange a private exchange before sharing details.

## Maintainers

See [the maintainer guide](.github/MAINTAINING.md) for review and credit retention. The GitHub workflow uses base-revision scripts on the tested merge commit with read-only access and does not run proposed scripts. Changes to the workflow, scripts, ownership and policy need owner review. Repository settings must require the checks and owner review; the PR workflow alone cannot enforce its own protection. For the PR introducing these checks, the preceding base cannot run the new checks, so review the bootstrap separately. Check links, dates, costs and attribution manually. Merging updates this repository. To sync curated Video or Design data, compare the source material or guide with the matching records in `video/` or `design/` (`canonical.json` and `inventory.json`), update the verified review date and refresh any snapshot details or hashes in [the Video README](video/README.md) or [the Design README](design/README.md). To feature a community workflow on the website, a maintainer selects it, preserves its credit and applicable license, and submits the change through the separate website editorial and deployment process.
